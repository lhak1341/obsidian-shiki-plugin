# Keep the stale-render guards in each consumer

`CodeBlock`, `InlineCodeBlock` and the CM6 view plugin each guard async renders with a generation counter, and the two `MarkdownRenderChild` classes add an `_active` flag. We considered a shared `RenderSlot` module (merging `_active` into the generation) and decided against it. Each guard is about six lines, so a shared module would be shallower than the code it replaces, and `CodeBlock.test.ts` and `InlineCodeBlock.test.ts` already pin the two `MarkdownRenderChild` guards through the class interface. The view plugin has no `_active` equivalent, so an in-flight `updateWidgets` keeps running after `destroy()`. That is harmless: CM6's `EditorView.update()` returns early on a destroyed view. Revisit if a fourth consumer appears or the guards start to diverge in behaviour.
